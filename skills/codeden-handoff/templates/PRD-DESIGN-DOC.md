# ICM Product Requirements / Design Specification

## 0 — Authority, provenance and mode
Mission ID and authenticated source, owner, proposed decision, GREENFIELD/BROWNFIELD/RESCUE, date, source versions, VERIFIED vs CLAIMED register.

## 1 — Customer and commercial thesis
Problem, who pays, evidence of purchase intent, existing alternatives, pricing hypothesis, capacity/cost, 30-day measurable outcome.

## 2 — Baseline and constraints
Current project state, existing code/repo links, protected areas, compliance/privacy, design system, approved external skills and licensing.

## 3 — Proposed smallest valuable slice
User journey, out-of-scope, functional requirements, negative cases, accessibility/mobile, error/recovery states.

## 4 — Technical design
Existing architecture/data flows, bounded change plan, tool permissions, secret handling, failure/retry/idempotency, dependencies and fallback.

## 5 — Measurable acceptance
Numbered tests with exact commands or manual reproduction; frontend screenshot baseline and mobile/desktop evidence if UI.

## 6 — Independent judge / release
Different reviewer/provider, PR-only changes, exact revision proof, CI/security checks, production verification only after separate explicit owner gate.

## 7 — Costs, stop and rollback
Authorized budget and time box, capacity, failure stop conditions, restore steps, accountable person, business impact.

## 8 — Handoff
Typed CodeDen issue URL, style-kit PR SHA, loaded skills, source evidence, unanswered questions, required owner approval.
