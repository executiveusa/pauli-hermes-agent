# Pauli Open Design

## triggers

- ui
- ux
- dashboard
- design system
- layout

## when_to_use

Use when the task needs reference-backed UI direction or a stronger interaction model.

## when_not_to_use

Do not use to justify generic SaaS patterns or unlabeled controls.

## required_tools

- file read
- browser-harness

## required_env

- none

## context_budget

- 3 design skills max

## safety_gates

- clarity first
- no mystery icons for critical actions

## workflow

1. Identify the primary user goal on the screen.
2. Tighten hierarchy, labels, and next actions.
3. Validate the result in-browser when possible.

## output_contract

- design direction
- key UI changes
- validation notes

## tests

- screen answers what this is, what to do, and what needs attention
