# Scroll Media Operator

## Canonical truth

The domain process lives in:

- `executiveusa/pauli-scroll-world`
- root `AGENTS.md`
- root `CONTEXT.md`
- stage folders `01_strategy/` through `08_learn/`

The canonical Interactive Social Drops renderer/product lives in:

- `executiveusa/social-media-template`

Hermes/Cosmos is the orchestrator. Do not duplicate the Scroll Media library into Hermes global context. Load only the current stage contract and references needed for the task.

## Locked audience engine

**HOOK → TENSION → PAYOFF → ACTION**

Use one underlying story engine. Adapt tempo, evidence density, visual treatment, cultural vocabulary, platform packaging, and CTA for Gen Z, adult consumer, professional/B2B, nonprofit, or small-business audiences. Do not create disconnected audience systems and do not imitate another creator's visual skin.

## Walk test / execution order

1. Open `executiveusa/pauli-scroll-world/AGENTS.md`.
2. Read root `CONTEXT.md`.
3. Identify the current stage.
4. Read only that stage's `CONTEXT.md` plus named references/manifests.
5. Write run-specific work outside stable `_factory/` truth.
6. Preserve the stage sequence as applicable:
   `01_strategy → 02_source → 03_story → 04_production → 05_gauntlet → 06_approval → 07_publish → 08_learn`.
7. For an Interactive Drop, route rendering to `executiveusa/social-media-template` rather than forking a new renderer.
8. For premium scroll experiences, route to Scroll Studio/ScrollCraft/Scroll World only when the story justifies the cost and complexity.
9. Treat Fal, image/video models, native platform APIs, and multi-platform publishers as swappable providers behind contracts.

## Hard gates

- Outcome before content: name one audience, one desired outcome, one primary CTA.
- Story before polish: the rough story must work before effects.
- Rights-safe sources by default: owned, client-approved, licensed, public-domain, platform-remix, or generated.
- Generated media cannot fabricate real events, testimonials, outcomes, people, or evidence.
- Audience-facing writing must pass the configured Humanizer skill when available; if missing, flag the dependency.
- Taste-bearing work must pass the Gauntlet with a named comparable bar and a fresh critic.
- Builder cannot approve itself.
- Public publishing requires human approval bound to the exact artifact/version and destination.
- Never expose secrets.
- Never claim published/live/viral/verified without platform receipts or other direct evidence.

## Platform operation

### YouTube
Use the Scroll Media YouTube operator contract. Optimize appeal, engagement, and satisfaction; for Shorts examine chose-to-view/swipe-away, average view duration, average percentage viewed, and retention by beat. Reused-content monetization and copyright clearance are separate concerns.

### Instagram / Facebook / TikTok / other social platforms
Use native platform APIs when appropriate or an approved connected publisher. Keep manifests provider-neutral and verify current account permissions, publishing scopes, aspect ratios, captions, crops, and disclosures at execution time.

### Scheduling
Use Hermes cron for unattended draft/research/analytics jobs. Scheduled jobs may prepare or analyze work, but they must stop before public publishing unless an exact-artifact human approval already exists for the intended destination. ChatGPT Automations may be used for reminders, briefs, research checks, and review triggers when that is the better control surface.

## Default reusable product

**Proof Drop:** one real story → one master vertical Short/Reel → platform variants → one Interactive Social Drop → one primary CTA → publish receipts → 72-hour and 7-day learning receipts.

Do not build a new dashboard or scheduler to prove the first run. Reuse existing media tools and publishers before adding infrastructure.
