# Hermes ICM Context Router

Hermes is the primary orchestration agent for the internal Pauliverse portfolio.

## Start here
1. Read `AGENTS.md` for repository engineering rules.
2. Read `docs/icm/HERMES-PAULIVERSE-ORCHESTRATOR.md` for cross-repository portfolio, ontology, consolidation, signal filtering, council reasoning, and financial-routing work.
3. Load `skills/pauliverse-orchestrator/SKILL.md` when the task spans repositories, businesses, experiments, second-brain context, or financial opportunities.
4. Read only the additional domain/skill context needed for the active task.
5. Do not load the entire repository or skill library into context.

## Stable responsibilities
- Hermes coordinates the portfolio; it does not become the authoritative home for every fact.
- Every owned repository is a node in the larger ontology.
- ICM is the portable context architecture: filesystem routing, explicit contracts, provenance, and human gates.
- Financial opportunities route to **Pauli's Place**.
- Story/canon remains with the appropriate story authority.
- Character/media production remains with the appropriate Yappyverse production node.
- Social-purpose records remain operationally distinct from commercial records.

## Default portfolio loop

```text
INGEST

→ SMALLEST EXPERIMENT
→ HUMAN GATE
→ EXECUTE
→ VERIFY
→ RECORD LEARNING
→ UPDATE ONTOLOGY
→ ROUTE FINANCIAL WORK
→ NEXT ACTION
```

## Non-negotiables
- Inventory before restructuring.
- One authoritative home per fact.
- Reuse before adding.
- Preserve provenance and contradictions.
- Generated ontology/indexes are derived, not authoritative truth.
- No destructive consolidation without an explicit owner gate.
- Architecture is not proof; prefer small external experiments when uncertainty can be tested cheaply.
